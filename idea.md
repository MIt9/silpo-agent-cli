Ось 5 **конкретних** CLI-концептів, які добре лягають і під хакатон, і під твій профіль як розробника, що вже працює з MCP, агентами та CLI-UX. Формат CLI тут не просто “для гіків”, а спосіб показати швидкий агентний сценарій, зовнішню інтеграцію або навіть окремий продукт, що прямо відповідає формату хакатону.[1]

## 1. WeekCart CLI

CLI-агент для тижневої закупівлі під бюджет, кількість людей і харчові обмеження. Це найпростіший шлях до сильної demo, бо проблема зрозуміла, цінність очевидна, а сценарій природно використовує MCP як “двигун” кошика.[1]

**Як працює:**
- `silpo-agent week --people 2 --days 7 --budget 2500`
- або `silpo-agent "збери закупівлю на тиждень для двох до 2500 грн"`

**Що робить агент:**
- дістає активний кошик і контекст доставки;
- враховує food restrictions, favorites, минулі замовлення;
- підбирає продукти по категоріях;
- оптимізує суму під бюджет;
- додає в кошик;
- пропонує бонуси, акції, checkout. Інструменти профілю, кошика, товарів, акцій і лояльності якраз описані в MCP-документації.[2]

**Чому сильна ідея:**
- легко пояснити за 15 секунд;
- добре показує агентність;
- має чітку користь для гостя;
- можна показати метрику “час до готового кошика”.[1]

## 2. DinnerParty CLI

CLI для сценаріїв “подія / вечеря / пікнік / шашлик / день народження”, де агент формує кошик під кількість гостей, формат події і бюджет. Це виглядає більш “wow”, ніж weekly cart, і добре продається у відеопітчі.[1]

**Приклади:**
- `silpo-agent event --type picnic --guests 8 --budget 1800`
- `silpo-agent "збери кошик для вечері на 6 людей, одна людина вегетаріанка"`

**Що агент робить:**
- генерує shopping plan;
- знаходить релевантні товари;
- підтягує альтернативи, якщо щось недоступне;
- тримає бюджет;
- кладе все в кошик;
- показує короткий breakdown: напої, основне, снеки, десерт.

**Фішка:**
CLI може працювати як “party copilot”, а не як просто shell wrapper над товарами. Це добре відповідає вимозі вирішувати конкретну проблему гостя, а не робити загальний FAQ-бот.[1]

## 3. Reorder Optimizer CLI

CLI, який бере минулі замовлення користувача й готує **оптимізований повтор**: з урахуванням акцій, наявності, дешевших аналогів і бонусів. Для користувача це дуже практично, а для журі це виглядає як продуктова, а не декоративна AI-фіча.[2][1]

**Приклади:**
- `silpo-agent reorder last`
- `silpo-agent reorder --from "2026-07-10" --optimize promos`
- `silpo-agent "повтори мою типову закупівлю, але дешевше"`

**Що агент робить:**
- бере історію online orders;
- витягує повторювані патерни;
- перевіряє, що доступно зараз;
- підбирає replacements;
- порівнює варіанти по бюджету;
- додає кращий сет у кошик.

**Чому це круто:**
- сильна value proposition;
- мінімум пояснень користувачу;
- добре використовує orders + products + replacements + loyalty. Ці блоки прямо є в MCP-можливостях.[2]

## 4. Budget Guardian CLI

CLI-агент, який не просто збирає кошик, а **охороняє бюджет**: підбирає дешевші товари, прибирає зайве, пропонує заміни й пояснює, чому сума вийшла такою. Для українського ринку така цінність дуже зрозуміла, а користь легко валідовувати.[1]

**Приклади:**
- `silpo-agent budget --goal 1200 --list shopping.txt`
- `silpo-agent "збери цей список і вкладися в 1000 грн"`
- `silpo-agent cart audit --max 1500`

**Що агент робить:**
- збирає список;
- ранжує товари за критичністю;
- знаходить дешевші аналоги;
- повідомляє, де бюджет ламається;
- пропонує режими: `strict`, `balanced`, `quality-first`;
- після підтвердження оновлює кошик.

**Сильна demo-логіка:**
```bash
✓ 11/12 товарів знайдено
~ 2 позиції замінено дешевшими аналогами
! бюджет перевищено на 94 грн
? перейти в balanced mode? [Y/n]
```

Це дуже добре показує agent loop: аналіз → план → tool calls → перевірка → корекція.

## 5. Support Ops CLI

CLI не для гостя, а для внутрішніх процесів: support / operations assistant для діагностики доставки, слотів, адреси, availability та проблем кошика. Хакатон прямо допускає рішення для підтримки, магазинів, маркетингу, категорійного менеджменту, логістики та інших бізнес-функцій, тому такий концепт повністю в рамці.[1]

**Приклади:**
- `silpo-support diagnose-delivery --address "Вінниця, ..."`
- `silpo-support cart-check --cart-id ...`
- `silpo-support replacements --cart-id ...`
- `silpo-support slot-check --branch 123 --delivery DeliveryHome`

**Що агент робить:**
- знаходить координати адреси;
- перевіряє доступні типи доставки;
- шукає доступні магазини й тайм-слоти;
- аналізує, чому кошик не проходить валідацію;
- пропонує оператору наступний крок.

**Чому це може бути навіть сильніше:**
- менше очікувань до “масового UX”;
- більше B2B/business value;
- простіше обґрунтувати ROI: менше часу на обробку запитів, швидша діагностика проблем.[1]

## Які 2 я б радив тобі

З урахуванням того, що ти сильний у MCP, AI automation, CLI та product-minded engineering, найкраще для тебе виглядають:

| Концепт | Чому саме тобі |
|---|---|
| WeekCart CLI | Найпростіше зібрати сильний end-to-end прототип, дуже зрозуміла користь [1] |
| Reorder Optimizer CLI | Найбільш продуктова цінність, добре демонструє “розумний агент”, а не просто wrapper [2][1] |
| Support Ops CLI | Добре показує B2B/internal use case і може виглядати “серйозніше” для журі [1] |

WeekCart — найкращий для швидкого submission. Reorder Optimizer — найкращий для “виглядає як справжній продукт”. Support Ops — найкращий, якщо хочеш зіграти від бізнес-цінності, а не від consumer wow.[1]

## Як вибирати

Обирай не за “що технічно прикольніше”, а за трьома критеріями:

- чи можна показати demo за 2–3 хвилини;
- чи зрозуміє людина користь без довгого пояснення;
- чи є там справжній agent loop, а не просто одна команда до MCP.[1]

Якщо хочеш прагматично:
1. **WeekCart CLI** — safest bet.[1]
2. **Reorder Optimizer CLI** — strongest product story.[2][1]
3. **Support Ops CLI** — strongest business story.[1]
